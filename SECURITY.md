# Security policy

Report suspected vulnerabilities privately to the repository owners. Do not open a public issue containing credentials, exploit details, private infrastructure identifiers, or user data.

Include the affected route or component, impact, reproduction conditions, and any safe mitigation you have tested. The maintainers will acknowledge a report, assess severity, coordinate remediation, and publish an advisory when disclosure is safe.

The examples in this guide are educational. Test commands in an isolated environment, replace placeholders deliberately, preserve console or recovery access, and maintain verified backups before destructive storage, identity, networking, or database changes.
